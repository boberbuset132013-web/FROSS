# FROSS — настройка публикации

## 1. Firebase и вход через Google или email/пароль
1. Открой https://console.firebase.google.com/ и создай проект Firebase.
2. В настройках проекта добавь Web App. Скопируй объект конфигурации приложения.
3. В Firebase Console → Authentication → Sign-in method включи Google и Email/Password (Email/Password — именно пароль, не email link). Phone/SMS не включай.
4. В Authentication → Settings → Authorized domains добавь домен `fross.boberbuset132013.workers.dev`.
5. В Firebase Console → Firestore Database создай базу данных.
6. Открой `public/firebase-config.js` в GitHub и замени все значения `YOUR_...` на значения из Firebase Web App. Это публичная конфигурация клиента; не вставляй сюда service-account JSON или приватный ключ.
7. В Firestore → Rules вставь содержимое файла `firestore.rules` и опубликуй правила.

При первом входе через Google аккаунт создаётся автоматически. Через email пользователь может зарегистрироваться, придумать пароль, войти позже и запросить письмо для сброса пароля. SMS/номер телефона не используются.

## 2. FROSS 1.1 с Generative Brain 1.0

Основной путь генерации работает в JavaScript Worker: если задан секрет `FROSS_LLM_API_KEY`, Worker обращается к настоящей языковой модели через OpenAI-совместимый API и получает свободно сгенерированный ответ. По умолчанию предусмотрены endpoint Groq и модель `openai/gpt-oss-20b`; их можно заменить переменными `FROSS_LLM_API_URL` и `FROSS_LLM_MODEL`. Для режима «Рассуждение» отправляется больший бюджет генерации. Это не гарантирует правильность ответа, но убирает ограничение «только заранее написанные фразы».

Когда Worker не может вызвать модель, сохраняются резервные пути:
- обычный режим → Python-сервис (`services/python-brain/server.py`): генерация через ту же конфигурацию LLM, затем локальные правила и нейросетевой классификатор намерений;
- режим «Рассуждение» → C++-планировщик (`services/cpp-brain/main.cpp`) и Python HTTP-обёртка: C++ предлагает локальную проверку/кандидат, а настроенная языковая модель формирует итог; при сбое остаётся локальный алгоритм;
- если модель и сервисы недоступны, Worker использует локальный JavaScript-движок.

### Подключение генеративной модели (рекомендуется)

1. Создай API-ключ в панели выбранного поставщика модели. Например, Groq предоставляет OpenAI-совместимый endpoint `https://api.groq.com/openai/v1/chat/completions`; документация: [API reference](https://console.groq.com/docs/api-reference) и [список моделей](https://console.groq.com/docs/models).
2. В Cloudflare Dashboard открой **Workers & Pages → fross → Settings → Variables and Secrets** и создай **Secret** с именем `FROSS_LLM_API_KEY`. Вставляй ключ только в поле Secret — не в GitHub, HTML, чаты или `wrangler.jsonc`.
3. При использовании Groq можно оставить значения по умолчанию. При другом OpenAI-совместимом поставщике добавь текстовые переменные:
   - `FROSS_LLM_API_URL` — полный HTTPS URL endpoint-а `/chat/completions`;
   - `FROSS_LLM_MODEL` — точный идентификатор модели из панели поставщика.
4. Сохрани настройки и выполни Deploy Worker. Проверь `/api/health`: поле `languageModelConfigured` должно быть `true`. Затем задай обычный открытый вопрос; в ответе диагностики ожидается `aiUsed: true`.
5. Чтобы отдельные Render-сервисы тоже могли генерировать ответы независимо от Worker, добавь те же переменные в Environment обоих сервисов. Это необязательно: основная интеграция работает в Worker.

FROSS больше не должен искать в интернете для каждого обычного вопроса: при настроенной модели веб-поиск вызывается по явной просьбе найти информацию/источники или проверить актуальные данные. Без API-ключа сохраняется прежний резервный режим и его ограниченная алгоритмическая генерация.

### Голосовой ввод

Кнопка **«Голос»** использует `SpeechRecognition` / `webkitSpeechRecognition` браузера с языком `ru-RU`. В актуальном Chrome нужен доступ к микрофону и, в зависимости от реализации браузера, подключение к интернету. Распознанная речь вставляется в поле сообщения как редактируемый текст; она не отправляется автоматически. Это распознавание речи браузером, а не отдельная модель, запущенная на сервере.

## 3. Подключение Python и C++ сервисов бесплатно
Проекты сервисов уже находятся в репозитории; файл `render.yaml` описывает два Docker-сервиса с планом Free. Render Free может приостанавливать неактивные сервисы, поэтому первый запрос после перерыва может быть медленнее или перейти на резервный JavaScript-ответ. Подробности: [официальные ограничения Render Free](https://render.com/docs/free).

1. Открой [Render](https://render.com/) и создай Blueprint, выбрав репозиторий `boberbuset132013-web/FROSS`. Render должен прочитать файл `render.yaml` и предложить `fross-python-brain` и `fross-cpp-brain`. Выбирай **Free** у обоих; не выбирай платный план.
2. Создай один секретный токен в PowerShell:
   ```powershell
   [guid]::NewGuid().ToString("N") + [guid]::NewGuid().ToString("N")
   ```
   Вставь одинаковое значение в переменную `FROSS_BRAIN_SERVICE_TOKEN` для обоих Render-сервисов. Токен нельзя публиковать в GitHub, сообщениях чата или коде.
3. Дождись успешной сборки двух сервисов. В Render открой каждый сервис и скопируй его реальный публичный URL. Проверь, что адреса `/health` открываются и показывают версию 1.0.
4. В Cloudflare Dashboard открой **Workers & Pages → fross → Settings → Variables and Secrets**. Добавь текстовые переменные:
   - `FROSS_PYTHON_BRAIN_URL` = URL Python-сервиса с путём `/chat`, например `https://ИМЯ-PYTHON-СЕРВИСА.onrender.com/chat`;
   - `FROSS_CPP_BRAIN_URL` = URL C++-сервиса с путём `/chat`, например `https://ИМЯ-CPP-СЕРВИСА.onrender.com/chat`.
   
   Вместо примеров вставь адреса, которые реально показал Render.
5. Там же добавь **Secret** с именем `FROSS_BRAIN_SERVICE_TOKEN` и вставь точно такой же токен, как в обоих Render-сервисах. Не сохраняй его в `wrangler.jsonc` или других публичных файлах. Сохрани переменные и выполни новый deploy Worker, если Dashboard не сделал это автоматически.
6. После этого Python и C++ сервисы будут доступны как резервные генеративные движки, если для них также заданы `FROSS_LLM_API_KEY`, `FROSS_LLM_API_URL` и `FROSS_LLM_MODEL`. Основная генерация сайта выполняется Worker-ом при настроенном `FROSS_LLM_API_KEY`; при сбое провайдера включаются резервные алгоритмы.

Официальная документация Render: [Blueprints](https://render.com/docs/blueprint-spec), [Free plan и ограничения](https://render.com/docs/free).

При включённых внешних движках текст нового сообщения и последние сообщения текущего чата могут быть переданы в Render-сервис Python или C++, вместе с выбранными заметками памяти. Сервисы настроены не записывать содержимое сообщений в журналы, но всё равно не отправляй в чат пароли, токены, закрытые ключи или другие секреты.

## 4. Пароль создателя, память и GitHub-база знаний
1. В Cloudflare Dashboard открой **Workers & Pages → fross → Settings → Variables and Secrets → Add → Secret**. Имя секрета — `FROSS_CREATOR_PASSWORD`; в значение введи новый уникальный пароль длиной не менее 24 символов. Не добавляй пароль в `vars`, GitHub, HTML, JavaScript, `wrangler.jsonc` или README. Если используешь Wrangler CLI, выполни `npx wrangler secret put FROSS_CREATOR_PASSWORD` и введи пароль в приглашении. [Документация Cloudflare Secrets](https://developers.cloudflare.com/workers/configuration/secrets/).
2. Для записи общих учебных материалов в GitHub создай **fine-grained personal access token** в GitHub → Settings → Developer settings → Fine-grained personal access tokens. Ограничь доступ только репозиторием `boberbuset132013-web/FROSS`; в Repository permissions установи **Contents: Read and write** (Metadata обычно требуется как Read-only). Для Contents API записи нужны права на чтение/запись содержимого репозитория: [официальная таблица прав GitHub](https://docs.github.com/en/rest/authentication/permissions-required-for-fine-grained-personal-access-tokens).
3. В Cloudflare → Workers & Pages → `fross` → Settings → Variables and Secrets → Add → Secret создай секрет `FROSS_GITHUB_TOKEN` и вставь в его значение выданный GitHub token. **Никогда не добавляй токен в публичный репозиторий, `vars`, HTML, сообщения или JSON.** Сохрани и выполни Deploy Worker. Если секрет не настроен, FROSS по-прежнему будет сохранять личные заметки в Firestore, но запись в GitHub будет выключена.
4. Войди в FROSS через Google или email/пароль и открой **«Обучение FROSS»**. Любой вошедший пользователь может изучать тему; для запуска общей автоучебы и публикации общих материалов нажми **«Стать создателем»** и введи пароль создателя. Сервер выдаёт подписанную сессию на 30 дней, привязанную к Firebase-пользователю; сайт хранит токен в localStorage, поэтому он переживает обновление страницы, открытие новой вкладки и перезапуск браузера. Для постоянного распознавания подтверждённой почты настрой `FROSS_CREATOR_EMAIL` (см. раздел 9).
5. В Firebase → Firestore Database → Rules опубликуй актуальный файл `firestore.rules`. Личные записи находятся в `users/{uid}/knowledge` и доступны только соответствующему вошедшему аккаунту.
6. Введи тему, например **«Основы Python»**, и нажми **«Изучить»**. FROSS собирает источники, извлекает краткое резюме, тезисы и ключевые слова и сохраняет заметки в приватной памяти этого аккаунта. Только авторизованный создатель может дополнительно публиковать общие учебные материалы в публичной папке `memory/knowledge/` и обновлять `memory/knowledge/index.json`. Не отправляй в публичную библиотеку личные сведения или историю чатов.
7. В последующих ответах FROSS ищет подходящие темы в общей GitHub-базе и комбинирует их с личными заметками Firestore и свежими результатами поиска. В интерфейсе есть ссылка **«Открыть базу GitHub»**. Вкладка GitHub — публичная, а Firestore остаётся личным хранилищем аккаунта.

**Важно о публичной памяти:** весь контент в `memory/knowledge/` виден всем читателям репозитория и остаётся в истории Git. Храни там только общие учебные сведения, выдержки из открытых источников, резюме, тезисы и ссылки. Не сохраняй личные переписки, имена/почту пользователя, пароли, секреты, токены или другие приватные данные.

Это память с извлечением знаний, а не изменение весов нейросети. Резюме создаётся выбором предложений из найденного текста и может быть неполным, поэтому перепроверяй важные утверждения по ссылкам.
### Автоматическое изучение JavaScript и Python

После публикации обновлённого `wrangler.jsonc` Worker запускает ежедневное фоновое изучение по расписанию `0 3 * * *` (03:00 UTC). Он ищет материалы по четырём темам: основы JavaScript, примеры кода JavaScript, основы Python и примеры кода Python; использует официальные руководства MDN и Python Docs вместе с результатами поиска, затем собирает выдержки и источники и обновляет `memory/knowledge/` в GitHub. В панели «Обучение FROSS» есть кнопка **«Изучить JS и Python сейчас»**, которая запускает тот же цикл без ожидания расписания. Для работы обязательно настрой Secret `FROSS_GITHUB_TOKEN` с разрешением Contents: Read and write. Если кнопка показывает ошибку конфигурации, создай Fine-grained personal access token в GitHub с доступом только к `boberbuset132013-web/FROSS` и правом **Contents: Read and write**, добавь его как Secret в Cloudflare и разверни Worker заново. Никогда не отправляй токен в чат. Кнопка **«Сохранить знания»** повторно сохраняет личные заметки в Firestore и не требует GitHub-токена; эта личная память не публикуется. Если секрет не задан, автоизучение пропускается; это видно в `/api/health` по полю `autoStudyConfigured`. Автоматическое изучение не сохраняет переписки пользователей в публичный репозиторий. Эта библиотека общая и публичная.

### Лимиты сообщения и память текущего чата

- Сообщение пользователя: максимум **30 000 символов**.
- Ответ FROSS: максимум **25 000 символов**.
- В контекст ответа передаются не более **пяти последних сообщений пользователя** и связанные с ними ответы ассистента. Полная история чата продолжает храниться в личной области Firestore пользователя, но более старые сообщения не отправляются движку как контекст текущего запроса.
- Кнопка автоизучения доступна только подтверждённому создателю и запускает фоновую задачу; прогресс и ошибки видны в Cloudflare → Workers & Pages → `fross` → Logs.
- После изменения `firestore.rules` обязательно опубликуй правила в Firebase Console → Firestore Database → Rules, иначе старый лимит 4 000 символов будет продолжать блокировать длинные сообщения.

### Обучаемая нейросеть Python (Brain 0.6)

Python-сервис использует отдельную маленькую нейросеть на NumPy, сделанную по базовой схеме из урока про нейросеть с нуля: признаки на входе → скрытый слой ReLU → выход softmax → ошибка классификации → обратное распространение ошибки. Здесь она распознаёт не картинки цифр, а типы коротких сообщений: приветствие, благодарность, продолжение разговора, просьбу объяснить причину, исправление понимания, сообщение об ошибке и другие разговорные намерения.

При сборке Docker-образа файл `services/python-brain/Dockerfile` устанавливает NumPy, обучает модель на помеченных примерах из `fross_neural_brain.py`, проверяет контрольные фразы и сохраняет веса в `fross-neural-model.npz`. При запуске Python-сервис загружает сохранённые веса; если файла модели нет, он попробует переобучить её на встроенных учебных примерах. В `/health` доступны поля `neuralModelLoaded`, `neuralModelVersion`, `neuralIntentCount` и `neuralTrainingAccuracy`.

Чтобы расширить классификацию, добавляй новые короткие фразы в `TRAINING_EXAMPLES` в `fross_neural_brain.py` и указывай правильный класс. После изменения исходников дождись пересборки Python-сервиса на Render. Обучение является контролируемым: модель учится на явно помеченных примерах, а не на личных переписках. Если модель недостаточно уверена, сервис не использует её ответ и продолжает обычную обработку. Важно: это нейросетевой классификатор намерений, а не генеративная языковая модель; он помогает понять тип реплики, но не умеет самостоятельно сочинять подробные ответы на любые темы. Без настроенного `FROSS_PYTHON_BRAIN_URL` Worker использует локальный JavaScript-резерв и этот Python-классификатор в чате не вызывается.

## 5. Публикация и проверка API
В Cloudflare Worker должно быть подключено это GitHub-репозитория. Команда развёртывания: `npx wrangler deploy`. Конфигурация `wrangler.jsonc` публикует папку `public` как статические файлы и передаёт запросы `/api/*` в Worker. После изменения репозитория дождись автоматического деплоя и обнови сайт сочетанием Ctrl+F5.

После публикации открой `https://fross.boberbuset132013.workers.dev/api/health`. Актуальная сборка должна вернуть JSON с `"version":"1.1"` и `"brainVersion":"0.6"`. Поля `creatorPasswordConfigured`, `githubKnowledgeConfigured`, `pythonBrainConfigured` и `cppBrainConfigured` показывают только факт настройки, не раскрывая значения секретов. Если вместо JSON приходит HTML, проверь маршрут/последнюю публикацию. Если API возвращает JSON с `errorId` и `diagnostic`, открой Cloudflare → Workers & Pages → `fross` → **Logs / Observability → Real-time Logs** и найди ошибку с этим ID: ответ API теперь логирует stack trace, а в чат отдаёт краткую диагностику. Никогда не отправляй в чат или логи значения секретов.

## 6. Возможности
- Вход/регистрация через Google и email/пароль.
- Восстановление пароля по email.
- Отдельные чаты с историей, сохранённой в Firestore.
- До 60 сообщений пользователя в каждом чате; на 60-м сообщение чат закрывается и становится доступен только для чтения. Можно создать новый чат.
- Анимация ответа «думает / ищет / формулирует».
- FROSS Brain 0.6 использует собственные правила, коррекцию частых опечаток, безопасный вычислитель арифметики, личную базу понятий, ранжирование заметок и композицию нескольких тезисов в связное объяснение. Дополнительно есть алгоритмический слой диалога: он учитывает последние переданные реплики, обрабатывает короткие уточнения («подробнее», «почему?», «а если?»), подтверждения и отказ, исправления понимания и сообщения о сбоях. Он использует только контекст, который сайт передал в запросе; это не свободная генерация нейросети.
- Входящий API-запрос проверяет Firebase ID token и владельца чата.

## 7. Удаление чатов
В боковой панели рядом с каждым чатом есть кнопка `×`. Она удаляет сообщения этого чата и сам документ чата. Для этого нужно опубликовать обновлённые правила из `firestore.rules`: удалять документы может только вошедший владелец соответствующего пользователя. Старые чаты и их история будут удалены без возможности восстановления.

## 8. Если не работает
- Ошибка конфигурации/кнопка Google выключена: проверь `public/firebase-config.js`.
- `Unexpected token '<'` или сообщение `вернул HTML вместо JSON`: API получил HTML-страницу вместо JSON. Обычно сайт обслуживается старой/не той публикацией или маршруты `/api/*` не попадают в Worker. Проверь `wrangler.jsonc` (в `assets.run_worker_first` должен быть `"/api/*"`), сделай Deploy актуального Worker и обнови сайт через Ctrl+F5. В обычном чате запрос должен идти на `/api/chat`; секрет создателя сам по себе эту ошибку не вызывает.
- Не получается стать создателем: сначала войди в FROSS и открой `https://fross.boberbuset132013.workers.dev/api/health`. Если `creatorPasswordConfigured` равно `false`, в Cloudflare → Workers & Pages → `fross` → Settings → Variables and Secrets добавь именно **Secret** `FROSS_CREATOR_PASSWORD` длиной не менее 24 символов, сохрани и опубликуй новую версию Worker. Затем обнови сайт через Ctrl+F5 и введи это же значение в окне «Обучение FROSS». Если `creatorPasswordConfigured` равно `true`, проверь, что вводишь точное значение секрета без лишних пробелов. Альтернативная настройка `FROSS_CREATOR_EMAIL` работает только для совпадающего адреса с подтверждённой почтой Firebase. `FROSS_GITHUB_TOKEN` отвечает за запись общей базы знаний и сам по себе не даёт права создателя.
- `auth/unauthorized-domain`: добавь домен Worker в Firebase Authentication → Authorized domains.
- `Missing or insufficient permissions`: проверь опубликованные `firestore.rules`.
- Если ответ на продолжение диалога не подходит: слой общения Brain 0.6 связывает только распознанные короткие фразы с доступной историей и не умеет свободно рассуждать как большая языковая модель. Уточняй запрос конкретным предложением; для новых тем включён поиск, а дальнейшие улучшения добавляй в `fross-brain.js`, `fross_brain_v05.py` и `services/cpp-brain/main.cpp`.
- После изменений дождись завершения автоматического деплоя и обнови страницу сочетанием Ctrl+F5.


## 9. Приватное распознавание создателя (настраивается отдельно)

**Рекомендуемый способ не терять права создателя:** настроить `FROSS_CREATOR_EMAIL`. Это привязывает права к проверенному Firebase email на сервере, а не только к временному токену браузера. Не сохраняй email в публичном HTML или GitHub-коде.
Чтобы FROSS узнавал авторизованный аккаунт создателя, не добавляй адрес электронной почты в исходный код или публичные файлы GitHub. В Cloudflare Dashboard открой Workers & Pages → выбери Worker `fross` → Settings → Variables and Secrets → Add → Secret. Имя секрета: `FROSS_CREATOR_EMAIL`. В значение вставь личный адрес создателя, затем сохрани секрет и выполни новый deploy, если Dashboard его запросит.

Worker сравнивает секрет с email в проверенном Firebase ID token; адрес должен быть подтверждён Firebase (`email_verified = true`). Подтверждённый Google-вход обычно подходит. Если используешь email/пароль, аккаунт должен пройти подтверждение почты. Сам email не передаётся движку ответов и не хранится в публичном репозитории. Сервер использует его только для проверки флага создателя. Для связи с автором указывается только публичный Telegram.
