# FROSS — настройка публикации

## 1. Firebase и вход через Google или email/пароль
1. Открой https://console.firebase.google.com/ и создай проект Firebase.
2. В настройках проекта добавь Web App. Скопируй объект конфигурации приложения.
3. В Firebase Console → Authentication → Sign-in method включи Google и Email/Password (Email/Password — именно пароль, не email link). Phone/SMS не включай.
4. В Authentication → Settings → Authorized domains добавь домен `fross.boberbuset132013.workers.dev`.
5. В Firebase Console → Firestore Database создай базу данных.
6. Открой `public/firebase-config.js` в GitHub и замени все значения `YOUR_...` на значения из Firebase Web App. Это публичная конфигурация клиента; не вставляй сюда service-account JSON или приватный ключ.
7. В Firestore → Rules вставь содержимое файла `firestore.rules` и опубликуй правила.

При первом входе через Google аккаунт создаётся автоматически. Через email пользователь может зарегистрироваться, придумать пароль, войти позже и запросить письмо для сброса пароля. SMS/номер телефона не используются.

## 2. FROSS Transformer Brain 1.4 — собственная генеративная модель

FROSS использует собственный decoder-only Transformer из `fross_transformer.py`. Готовые языковые модели, скачанные веса и внешние LLM API не подключаются. BPE-токенизатор строится по своему корпусу, веса инициализируются случайно и обучаются через cross-entropy, backpropagation и AdamW. В модели пять Transformer-блоков с четырьмя attention-головами в каждом; входной контекст — до 320 токенов, а длина генерации — до 5 000 новых токенов. Также есть causal multi-head self-attention (Query/Key/Value), embeddings, feed-forward слои, residual connections и LayerNorm.

**Все ответы сайта — обычный режим и «Рассуждение» — идут в один Python-сервис.** Режим рассуждения использует другой prompt. Оба режима используют один Python backend и могут генерировать до 5 000 новых токенов. GitHub/Worker обслуживает сайт и API; Python-сервер загружает собственные веса и генерирует ответ. Сохранённые заметки и результаты явного поиска можно передать модели как дополнительный контекст, но это само по себе не меняет веса.

На момент этой версии учебный корпус содержит 328 оригинальных диалогов после добавления примеров понимания намерения пользователя, исправления недопонимания и письменных занятий по JS, Python, HTML, CSS и языкам. Это небольшой эксперимент: качество зависит от разнообразия корпуса и вычислительного бюджета. Если генерация не работает, сервис должен сообщить о проблеме с моделью, а не молча подставлять старый шаблон. Личные чаты не используются для автоматического переобучения. Корпус содержит подготовленные пары «пользователь — FROSS», чтобы обучать модель реагировать на уточнения и отвечать по смыслу; после изменения корпуса нужно заново собрать Python-сервис.

## 3. Подключение Python-мозга на Hostless

Python-мозг уже собирается как Docker-приложение `fross-python-brain` на Hostless. Worker FROSS по умолчанию использует адрес `https://fross-python-brain.hostless.app/chat`; переменную `FROSS_PYTHON_BRAIN_URL` можно не добавлять, если адрес не менялся.

1. В Hostless открой приложение `fross-python-brain` → Settings / Environment Variables (или Secrets).
2. Добавь переменную окружения `FROSS_BRAIN_SERVICE_TOKEN`. В значение помести общий случайный секрет для связи Worker ↔ Python-сервис. Используй минимум 16 символов; предпочтительно 32 или больше. Не добавляй его в GitHub, исходный код или файлы конфигурации. Сохрани настройки и перезапусти/разверни приложение, чтобы переменная попала в runtime.
3. В Cloudflare Dashboard открой **Workers & Pages → fross → Settings → Variables and Secrets** и добавь **Secret** с точно таким же именем `FROSS_BRAIN_SERVICE_TOKEN` и тем же значением. Не создавай обычную открытую Text variable для секрета.
   **Важно:** после сохранения Cloudflare намеренно скрывает значение секрета в интерфейсе — это не означает, что он удалился. В `wrangler.jsonc` указано, что этот секрет обязателен; развёртывание через Wrangler должно завершиться ошибкой, если секрет действительно отсутствует. Если после Deploy `pythonBrainConfigured` становится `false`, проверь, что открыт именно Worker `fross` и нужное окружение, затем заново добавь Secret и нажми **Deploy**.
4. Если адрес Hostless изменится, добавь Text variable `FROSS_PYTHON_BRAIN_URL` со значением полного HTTPS URL до маршрута `/chat`, например `https://имя-приложения.hostless.app/chat`. При текущем адресе это необязательно, потому что Worker уже содержит безопасный URL по умолчанию.
5. Выполни **Deploy** Worker в Cloudflare, если он не публикуется автоматически после обновления кода. В Hostless открой `https://fross-python-brain.hostless.app/health`: нужно увидеть `"generationModelLoaded": true` и `"generationModel": "FROSS Transformer 1.4"`.
6. Проверь `https://fross.boberbuset132013.workers.dev/api/health`. Ожидаются `"pythonBrainConfigured": true`, а внутри `pythonBrainHealth` — `"reachable": true` и `"generationModelLoaded": true`. Если `pythonBrainConfigured` равно `false`, проверь, что одинаковый токен установлен в Hostless и Cloudflare. Никогда не отправляй значение секрета в чат или логи.

## 4. Память и фоновая библиотека знаний

История чатов и личные данные остаются в Firestore. Файлы `memory/knowledge/` в GitHub — отдельная общая публичная библиотека на ветке `fross-knowledge`, чтобы новые заметки не попадали в `main` и не запускали пересборку Python-модели при каждом цикле обучения. Содержимое публичное, а изменения сохраняются в истории Git. В репозитории уже добавлены начальные заметки по нейросетям/Transformer, JavaScript, Python, HTML и CSS; Worker читает их из публичных файлов без токена, но автоматическое пополнение требует Secret `FROSS_GITHUB_TOKEN`. Не размещай там переписки, имена, адреса, пароли, ключи, токены или другие приватные данные.

На экране входа, в боковой панели и в **Настройках** есть общая панель обучения, доступная также без аккаунта. **«Начать обучение»** выбирает следующую тему, а **«Найти тему и изучить»** принимает введённую тему. Учебная панель текстовая и без аудио; из программирования в плане только JavaScript, Python, HTML и CSS. Другие направления включают письменные материалы по английскому, китайскому и русскому, общие знания и понимание намерений пользователя. Автоматический режим запускает одну тему сразу и затем выбирает следующую примерно раз в 2 минуты, пока вкладка открыта. Кнопка «Стоп» запрещает новые циклы, а состояние можно сохранить в браузере и возобновить после перезагрузки. При закрытии вкладки сам браузерный таймер не работает. Worker также проверяет серверный cooldown: общий и устойчивый для всех посетителей при наличии `FROSS_GITHUB_TOKEN`, а без токена ограничение не является глобальным. Результаты пополняют справочную базу, но сами по себе **не переобучают веса Transformer**.

### Постепенное пополнение общей базы знаний

В общей панели можно задать тему для первого автоматического цикла или нажать «Старт автообучения», чтобы запустить сохранённую очередь из JavaScript, Python, HTML, CSS, письменных языковых тем и общих знаний. Следующие темы выбираются в браузере и сохраняются в локальных настройках. Worker собирает до 7 заметок из разных источников, отбрасывает повторяющиеся предложения и типовые элементы навигации, затем сохраняет заметки в личной памяти Firestore или браузера. Общая GitHub-база обновляется только при настроенном `FROSS_GITHUB_TOKEN`. Плановая задача Cloudflare `0 3 * * *` продолжает ежедневно обновлять общую библиотеку.

`FROSS_GITHUB_TOKEN` нужен только для публикации материалов в общую GitHub-базу. Если его нет, обучение всё равно выполняет поиск и показывает результаты: у вошедшего пользователя заметки сохраняются в личную Firestore-память FROSS, а у гостя — в `localStorage` браузера и импортируются в аккаунт после входа. Без секрета общая база не обновляется, а ограничение частоты действует только внутри экземпляра Worker. Для общего двухминутного лимита и автоматической публикации знаний подключи секрет.

**Как задать Secret:** в GitHub открой Settings → Developer settings → Fine-grained personal access tokens → Generate new token; разреши доступ только к репозиторию `boberbuset132013-web/FROSS`, установи Repository permissions → Contents: Read and write и создай токен. Затем в Cloudflare Dashboard → Workers & Pages → `fross` → Settings → Variables and Secrets → Add → Production добавь тип **Secret** с ключом `FROSS_GITHUB_TOKEN` и вставь созданное значение. Сохрани и нажми Deploy. Это отдельный токен GitHub; не используй вместо него `FROSS_BRAIN_SERVICE_TOKEN` и никогда не публикуй его в GitHub или чате.

Материалы из `memory/knowledge/` — публичные и могут использоваться как справочный контекст в ответах. Не добавляй туда переписки, приватные данные или секреты. Этот процесс **не меняет веса нейросети**; реальное обучение описано в следующем разделе.

### Лимиты сообщения и память текущего чата

- Сообщение пользователя: максимум **30 000 символов**.
- Ответ FROSS: максимум **50 000 символов** (до 5 000 новых токенов генерации, если модель не завершит ответ раньше).
- В контекст ответа передаются не более **пяти последних сообщений пользователя** и связанные с ними ответы ассистента. Полная история чата продолжает храниться в личной области Firestore пользователя, но более старые сообщения не отправляются движку как контекст текущего запроса.
- Кнопка «Пополнить знания FROSS без входа» доступна любому посетителю и запускает только один общий шаг раз в 2 минуты. Если `FROSS_GITHUB_TOKEN` не настроен, поиск и личное запоминание всё равно работают; в общей GitHub-базе новые материалы не появятся. Статус выполнения проверяй в Cloudflare → Workers & Pages → `fross` → Logs.
- После изменения `firestore.rules` обязательно опубликуй правила в Firebase Console → Firestore Database → Rules, иначе старый лимит 4 000 символов будет продолжать блокировать длинные сообщения.

### Обучение и проверка собственной генеративной модели

**Чтобы FROSS лучше понимал запросы, сначала нужно улучшить обучающий корпус, а затем пересобрать Python-сервис на Hostless.** Кнопка «Deploy» у Cloudflare Worker `fross` обновляет сайт и маршруты, но не запускает обучение Transformer.

1. Открой `data/fross_corpus.jsonl` в GitHub. Каждая строка должна быть отдельным корректным JSON-объектом с непустыми полями `user` и `assistant`. Например:

   ~~~json
   {"user":"Объясни, что такое переменная в Python, простыми словами.","assistant":"Переменная — это имя, связанное со значением. Например, age = 12 сохраняет число 12 в переменной age. Позже программа может использовать это значение по имени."}
   ~~~

2. Добавляй много **разнообразных качественных пар**: разные формулировки одного вопроса, приветствия, просьбы объяснить по шагам, уточнения, примеры кода с проверенным результатом, исправление типичных ошибок и ответы «не знаю», когда данных недостаточно. Ответ должен действительно отвечать на вопрос, а не просто содержать похожие слова. Не помещай в корпус личные переписки, пароли, секреты или чужие персональные данные. Сейчас корпус небольшой — около 328 пар, поэтому он недостаточен для надёжного понимания широкого набора запросов.

3. Закоммить изменения `data/fross_corpus.jsonl` в ветку `main`.

4. В Hostless открой приложение `fross-python-brain` и запусти **Rebuild / Redeploy** с последним коммитом. Его `services/python-brain/Dockerfile` заново обучает собственную модель на корпусе при сборке образа: для Brain 1.4 на первом этапе задано 600 шагов, batch size 4, контекст 320 токенов, словарь 5000 токенов, размер представления 192, 6 attention-голов и 6 Transformer-блоков. После проверки качества отдельными этапами планируются 3000, затем 5000 шагов. Это обучение **с нуля**, а не продолжение с предыдущих весов. Убедись, что именно образ Python-сервиса пересобрался успешно.

5. После сборки открой `https://fross-python-brain.hostless.app/health` и проверь `generationModelLoaded: true`, а также `training_examples` и `training_steps` в статусе модели. Затем проверь несколько запросов, которых не было в обучающих примерах, и оцени не только гладкость текста, но и правильность ответа.

Для локального запуска обучения (при установленном Python и PyTorch) используется команда, аналогичная Dockerfile:

~~~bash
python fross_transformer.py train --corpus data/fross_corpus.jsonl --output fross-transformer.pt --steps 600 --batch-size 4 --block-size 320 --vocab-size 5000
~~~

Для быстрой диагностики перед полноценным обучением:

~~~bash
python fross_transformer.py test --output /tmp/fross-transformer.pt --steps 12 --batch-size 2 --block-size 64 --merges 32
python tests/test_fross_transformer.py
~~~

Важно: повышение числа шагов само по себе не сделает маленькую модель умнее и может привести к переобучению. Вначале увеличивай разнообразие корпуса, затем измеряй validation loss и проверяй ответы на новых запросах. Текущая модель — небольшой эксперимент с примерно миллионом параметров (точное число зависит от словаря BPE), поэтому даже после улучшений её качество будет ограничено размером модели и объёмом данных.

## 5. Публикация и проверка API
В Cloudflare Worker должно быть подключено это GitHub-репозитория. Команда развёртывания: `npx wrangler deploy`. Конфигурация `wrangler.jsonc` публикует папку `public` как статические файлы и передаёт запросы `/api/*` в Worker. После изменения репозитория дождись автоматического деплоя и обнови сайт сочетанием Ctrl+F5.

После публикации открой `https://fross.boberbuset132013.workers.dev/api/health`. Актуальная сборка должна вернуть JSON с `\"version\":\"1.3\"`, `\"brainVersion\":\"1.4\"` и `\"build\":\"fross-hybrid-cpp-2026-10-26\"`. `pythonBrainHealth` показывает, доступен ли Python-сервис и загрузилась ли собственная модель. Если вместо JSON приходит HTML, проверь маршрут/последнюю публикацию. Если API возвращает JSON с `errorId` и `diagnostic`, открой Cloudflare → Workers & Pages → `fross` → **Logs / Observability → Real-time Logs** и найди ошибку с этим ID: ответ API теперь логирует stack trace, а в чат отдаёт краткую диагностику. Никогда не отправляй в чат или логи значения секретов.

## 6. Возможности
- Вход/регистрация через Google и email/пароль.
- Восстановление пароля по email.
- Отдельные чаты с историей, сохранённой в Firestore.
- Лимит чата — примерно **1 000 000 токенов** по оценке длины текста (около одного токена на три символа), вместо ограничения по числу сообщений. Полная история хранится в чате, но в активный контекст модели по-прежнему передаются только последние пять пользовательских сообщений с ответами. Максимум генерации 5 000 токенов — верхняя граница, а не гарантия длины; на CPU очень длинные ответы могут генерироваться медленно.
- Анимация ответа «думает / ищет / формулирует».
- FROSS Transformer 1.4 создаёт текст через собственные обученные веса, а не через готовые ответы. Оригинальная фраза пользователя сохраняется; при вопросах о терминах или незнакомых выражениях Worker дополнительно ищет их значения и передаёт найденные фрагменты как контекст. Обычный режим использует рабочий план из 7 этапов, «Рассуждение» — расширенный план из 14. Это этапы программного конвейера и инструкции модели, а не 7 или 14 отдельных нейросетей. Оба режима используют один Python-сервис.
- Входящий API-запрос проверяет Firebase ID token и владельца чата.

## 7. Удаление чатов
В боковой панели рядом с каждым чатом есть кнопка `×`. Она удаляет сообщения этого чата и сам документ чата. Для этого нужно опубликовать обновлённые правила из `firestore.rules`: удалять документы может только вошедший владелец соответствующего пользователя. Старые чаты и их история будут удалены без возможности восстановления.

## 8. Если не работает
- Ошибка конфигурации/кнопка Google выключена: проверь `public/firebase-config.js`.
- Друг не может открыть даже главную страницу и Chrome пишет «Не удаётся получить доступ к сайту»: это происходит до входа Firebase и до генерации ИИ. Сначала открой точный адрес `https://fross.boberbuset132013.workers.dev/api/health`. Если он тоже не открывается ни у кого, в Cloudflare → Workers & Pages → `fross` → Settings → Domains & Routes проверь, что `workers.dev` включён и отображаемый адрес совпадает с отправленной ссылкой; затем выполни Deploy последнего Worker. Если у тебя страница открывается, а у друга — нет, попроси его попробовать другую сеть и прислать точный код Chrome (`ERR_NAME_NOT_RESOLVED`, `ERR_CONNECTION_TIMED_OUT` и т. п.): это поможет отличить DNS от сетевого маршрута. Проверка кода в GitHub сама по себе не подтверждает, что опубликованный адрес доступен извне.
- `Unexpected token '<'` или сообщение `вернул HTML вместо JSON`: API получил HTML-страницу вместо JSON. Обычно сайт обслуживается старой/не той публикацией или маршруты `/api/*` не попадают в Worker. Проверь `wrangler.jsonc` (в `assets.run_worker_first` должен быть `"/api/*"`), сделай Deploy актуального Worker и обнови сайт через Ctrl+F5. В обычном чате запрос должен идти на `/api/chat`; секрет создателя сам по себе эту ошибку не вызывает.
- `auth/unauthorized-domain`: добавь домен Worker в Firebase Authentication → Authorized domains.
- `Missing or insufficient permissions`: проверь опубликованные `firestore.rules`.
- Если ответ слишком короткий или бессвязный: проверь `pythonBrainHealth.generationModelLoaded`, качество и разнообразие корпуса в `data/fross_corpus.jsonl`, а также validation loss. Добавляй оригинальные пары диалогов и пересобирай один Python-сервис. JavaScript нормализует запрос и маршрутизирует его; текст генерируется обученными весами Transformer.
- После изменений дождись завершения автоматического деплоя и обнови страницу сочетанием Ctrl+F5.


## 9. Приватное распознавание создателя (настраивается отдельно)


Worker сравнивает секрет с email в проверенном Firebase ID token; адрес должен быть подтверждён Firebase (`email_verified = true`). Подтверждённый Google-вход обычно подходит. Если используешь email/пароль, аккаунт должен пройти подтверждение почты. Сам email не передаётся движку ответов и не хранится в публичном репозитории. Сервер использует его только для проверки флага создателя. Для связи с автором указывается только публичный Telegram.
