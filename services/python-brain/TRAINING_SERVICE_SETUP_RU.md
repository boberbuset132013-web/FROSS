# Отдельный FROSS Training Service (Hostless)

Этот сервис выполняет только обучение Brain 1.6. Основной FROSS Python Brain остаётся отдельным inference-сервисом и продолжает обслуживать чат.

## 1. Создай второй Hostless app

Создай отдельное приложение из того же GitHub-репозитория `boberbuset132013-web/FROSS` и ветки, в которой находится эта конфигурация. Не меняй настройки существующего `fross-python-brain`.

Для нового приложения выбери Hostless File Path:

```text
hostless-training.yaml
```

Конфигурация использует тот же Dockerfile, но выделяет обучению отдельный runtime: до 4 vCPU и до 12 GB RAM, одна реплика.

## 2. Подключи постоянное хранилище

В разделе Storage подключи или создай Persistent Volume и смонтируй его строго в:

```text
/data
```

Рекомендуемый размер — 15 GB или больше, если Hostless предлагает такую опцию. Самое важное: checkpoint и статус обучения должны находиться внутри `/data`. Файлы вне каталога монтирования могут исчезнуть при пересоздании контейнера.

Не включай подтверждение постоянного диска до того, как volume действительно прикреплён к новому приложению и смонтирован в `/data`.

## 3. Добавь переменные окружения в новом Hostless app

Установи:

| Переменная | Значение |
|---|---|
| `FROSS_TRAINING_SERVICE_MODE` | `1` |
| `FROSS_TRAINING_STORAGE_CONFIRMED` | `1` — только после подключения volume к `/data` |
| `FROSS_TRAINING_DATA_DIR` | `/data/fross-training` |
| `FROSS_TRAINING_OUTPUT_PATH` | `/data/fross-training/fross-training-output-8k-64m.pt` |
| `FROSS_TRAINING_STATE_PATH` | `/data/fross-training/training-status.json` |
| `FROSS_CHECKPOINT_INTERVAL_STEPS` | `500` |
| `FROSS_TORCH_THREADS` | `2` |
| `FROSS_DEVICE` | `cpu` |
| `FROSS_BRAIN_SERVICE_TOKEN` | Точно такое же значение, как у основного Python Brain и Cloudflare Worker |

Не вставляй токен в GitHub, файлы репозитория, публичные сообщения или браузер. Вводи его только в защищённое поле секретов Hostless.

## 4. Подключи Cloudflare Worker к новому сервису

В настройках переменных Worker добавь обычную переменную (не секрет):

```text
FROSS_TRAINING_SERVICE_URL=https://АДРЕС-НОВОГО-TRAINING-APP.hostless.app
```

Укажи настоящий домен созданного второго приложения, без `/chat`, без завершающего пути и без пробелов.

Оставь существующий `FROSS_PYTHON_BRAIN_URL` как есть: он продолжает указывать на текущий сервис генерации чата. Секрет `FROSS_BRAIN_SERVICE_TOKEN` должен совпадать во всех трёх местах: в Worker, основном Python Brain и Training Service.

## 5. Проверка перед первым запуском

Открой адрес нового приложения с путём `/health`. В JSON должны быть:

- `trainingServiceMode: true`
- `trainingStorageReady: true`
- `ok: true`

Если `trainingStorageReady: false`, не запускай обучение: проверь volume и переменные из шага 3.

После успешной проверки открой FROSS → «Обучение». Убедись, что статус читается и журнал доступен. Только затем запускай первый этап.

## Как теперь сохраняется прогресс

Полная возобновляемая checkpoint-копия будет записываться каждые 500 шагов. Она включает веса последнего состояния, веса лучшей проверки, состояние AdamW и состояния генераторов случайных чисел. После перезапуска training app панель покажет последний сохранённый шаг; можно выбрать следующую большую цель, и обучение продолжится с checkpoint.

Чат и обучение выполняются в разных контейнерах. Training app не загружает рабочую модель инференса и не должен запускать больше одной реплики. Файл для публикации модели станет доступен после достижения 100 000 шагов.

## Важное ограничение

Эта конфигурация и код не создают Hostless-приложение, не подключают платный volume и не добавляют Worker-переменную автоматически. Эти три действия нужно выполнить в панелях Hostless/Cloudflare. До их завершения Worker намеренно не отправляет запуск обучения в основной чат-сервис.
