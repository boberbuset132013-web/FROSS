# FROSS website 1.3 · Transformer Brain 1.4

FROSS is a Russian-language experimental assistant with a decoder-only Transformer implemented and trained from scratch, an original corpus and tokenizer, a Python generation service, saved chat history, and private learning memory.

## Local training on Windows

To train on your own PC in two stages — **600 steps, then continue to 3,000 total steps** — follow [the Windows training guide](training/windows/README_RU.md). The scripts save and restore model weights, the AdamW optimizer, random-number-generator state, corpus hash, step count, and one continuous learning-rate schedule. Training artifacts stay local and are not pushed to GitHub or automatically deployed to Hostless.

## First-time setup
Follow [SETUP.md](SETUP.md) before signing in. Firebase Web App values must be added to `public/firebase-config.js`, Google sign-in enabled, the Firestore database created, and `firestore.rules` published.

The response generator is our own small decoder-only Transformer in `fross_transformer.py`: a corpus-trained BPE tokenizer, token and positional embeddings, causal multi-head self-attention, feed-forward blocks, residual connections, LayerNorm, and next-token sampling. Weights are initialized randomly, trained locally during the Python service's Docker build on a validated, deduplicated merge of `data/fross_corpus.jsonl` and `data/fross_teacher_corpus.jsonl`, and saved as a checkpoint. The FROSS student starts from random weights and does not load a pretrained checkpoint or call a hosted LLM API at inference time. Optional local teacher generation is a separate data-preparation step that stores text examples only. The Worker routes both normal and reasoning mode to that same Python service. A task-aware response strategy now guides greetings, translations, code requests, limited edits, explanations and contextual follow-ups; reasoning mode adds a 14-stage working plan while normal mode uses 7 stages. These stages are instructions in one model pipeline, not separate neural networks. If the checkpoint is missing, the service reports an error instead of silently replacing a substantive answer with a canned template. Web search is used for recent facts, explicit source requests, term explanations, technical questions, and selected unfamiliar phrases. The Worker keeps the user's original wording and prioritizes current search results in the model context; results support the model's response but do not update weights automatically. The model is still a small experiment: the training set currently combines 328 original dialogue pairs with 82 curated teacher-generated examples. An optional local teacher utility can add more synthetic pairs; teacher weights are never copied into FROSS. Brain 1.4 starts with 600 CPU steps, targets a 5,000-token word-boundary BPE vocabulary, and uses a wider/deeper 192-dimensional, 6-head, 6-block Transformer. The next training stages are 3,000 and then 5,000 steps, with validation and held-out prompts checked between stages. The vocabulary target does not mean all 5,000 tokens are well learned: the small corpus must also grow substantially before fluent, reliable output should be expected. The visitor-facing learning buttons have been hidden from the website UI. The related backend and browser code remain in the repository, but these controls are not displayed. For local Transformer training on Windows, follow the guide in `training/windows/README_RU.md`. With no GitHub token, only browser timers and the Worker-isolate cooldown apply; shared knowledge publication requires `FROSS_GITHUB_TOKEN`; the live public knowledge store is on the separate `fross-knowledge` branch so every study cycle does not retrigger a main-branch model build. The programming curriculum is limited to JavaScript, Python, HTML, and CSS; language-learning topics use text, not audio. New curated dialogue examples train the model to respond to user intent and corrections. Adding reference notes alone does not update Transformer weights; after changing either training corpus, rebuild the Python service. `FROSS_GITHUB_TOKEN` is for publishing the separate shared knowledge library and is not required for model training. The daily Cloudflare Cron Trigger continues updating the knowledge library. These sources provide optional context but do not change Transformer weights. For local training on Windows, run `training/windows/START_TRAIN_600.bat` and then `CONTINUE_TO_3000.bat` as described in the training guide. The optional `TEACH_FROSS.bat` uses a local Ollama model only to generate text examples. FROSS is the only model whose weights are trained; the local 3,000-step checkpoint is not uploaded or deployed automatically. When the Python Docker service is rebuilt, it combines both committed corpora and trains a fresh FROSS student from random weights. The response limit is 50,000 characters, each user message is limited to 30,000 characters, and only the last five user turns with related assistant replies are sent as active chat context. FROSS Brain 1.4 uses a 7-stage normal response workflow and a 14-stage extended reasoning workflow. The Transformer still uses shared learned layers rather than separate, manually assigned 'word neurons'; the stages organize the request/retrieval/validation pipeline. It has a 320-token input context, width 192, 6 attention heads, 6 Transformer blocks, and a 5,000-token target vocabulary. The new BPE tokenizer learns word/whitespace/punctuation segments independently so learned tokens cannot span multiple words. The output cap is separate from the input context length. A chat can store approximately 1,000,000 estimated tokens (roughly one token per three characters); only the latest five user turns with related assistant replies are sent as active context, and long CPU generations may be slow. Follow `SETUP.md` to configure the services and secrets. Never store chats, passwords, tokens, or personal information in the public GitHub knowledge library. When connected, recent chat text is sent to the configured Python generation service; do not send passwords, tokens or private keys.
