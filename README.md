# FROSS 1.2 · Transformer Brain 1.2

FROSS is a Russian-language experimental assistant with a decoder-only Transformer implemented and trained from scratch, an original corpus and tokenizer, a Python generation service, saved chat history, and private learning memory.

## First-time setup
Follow [SETUP.md](SETUP.md) before signing in. Firebase Web App values must be added to `public/firebase-config.js`, Google sign-in enabled, the Firestore database created, and `firestore.rules` published.

The response generator is our own small decoder-only Transformer in `fross_transformer.py`: a corpus-trained BPE tokenizer, token and positional embeddings, causal multi-head self-attention, feed-forward blocks, residual connections, LayerNorm, and next-token sampling. Weights are initialized randomly, trained locally during the single Python service's Docker build on the original Russian corpus in `data/fross_corpus.jsonl`, and saved as a checkpoint. No pretrained language model, downloaded weights, or hosted LLM API is used. The Worker routes both normal and reasoning mode to that same Python service. A task-aware response strategy now guides greetings, translations, code requests, limited edits, explanations and contextual follow-ups; reasoning mode adds a 14-stage working plan while normal mode uses 7 stages. These stages are instructions in one model pipeline, not separate neural networks. If the checkpoint is missing, the service reports an error instead of silently replacing a substantive answer with a canned template. Web search is used for recent facts, explicit source requests, term explanations, technical questions, and selected unfamiliar phrases. The Worker keeps the user's original wording and prioritizes current search results in the model context; results support the model's response but do not update weights automatically. The model is still a small experiment: it has 328 original training pairs (including 30 context-aware multi-turn examples and word-meaning examples) and is trained for 3000 CPU steps. It cannot provide the knowledge or reliability of a large-scale language model; quality must be measured against held-out examples and improved with more data and compute. A temporary “Grow FROSS knowledge” button is available to all visitors, including guests who are not signed in. It collects one text-only topic at a time, with a two-minute browser loop while the tab stays open, plus a server-side cooldown. The loop has Start and Stop controls and resumes after a page reload when enabled. With no GitHub token, only browser timers and the Worker-isolate cooldown apply; shared knowledge publication requires `FROSS_GITHUB_TOKEN`; the live public knowledge store is on the separate `fross-knowledge` branch so every study cycle does not retrigger a main-branch model build. The programming curriculum is limited to JavaScript, Python, HTML, and CSS; language-learning topics use text, not audio. New curated dialogue examples train the model to respond to user intent and corrections. Adding reference notes alone does not update Transformer weights; after changing `data/fross_corpus.jsonl`, rebuild the Python service. This requires the `FROSS_GITHUB_TOKEN` Cloudflare Secret with Contents: Read and write access to this repository. The daily Cloudflare Cron Trigger continues updating the knowledge library. These sources provide optional context but do not change Transformer weights. To train the model, add curated user/assistant pairs to `data/fross_corpus.jsonl` and rebuild the `fross-python-brain` Docker service on Hostless; its Dockerfile trains the model from scratch during image build. The response limit is 25,000 characters, each user message is limited to 30,000 characters, and only the last five user turns with related assistant replies are sent as active chat context. FROSS Brain 1.2 uses a 7-stage normal response workflow and a 14-stage extended reasoning workflow. The Transformer still uses shared learned layers rather than separate, manually assigned 'word neurons'; the stages organize the request/retrieval/validation pipeline. It has a 320-token input context, 4 attention heads, and 5 Transformer blocks; output generation is capped at 650 new tokens per reply. The output cap is separate from the input context length. Follow `SETUP.md` to configure the services and secrets. Never store chats, passwords, tokens, or personal information in the public GitHub knowledge library. When connected, recent chat text is sent to the configured Python generation service; do not send passwords, tokens or private keys.
