# FROSS training experiments

This folder contains a reproducible comparison runner. It does **not** change the live
Worker or replace the production checkpoint by itself.

## Variants

- \`baseline\`: current Docker build setting, 3,000 steps on \`data/fross_corpus.jsonl\`.
- \`more_steps\`: same corpus and setup, 5,000 steps.
- \`teacher_augmented\`: the base corpus plus a separately reviewed teacher-answer corpus,
  trained for the same 5,000 steps.

The repository Dockerfile already uses **3,000 steps**. The Python CLI default of 600 is
only used when \`--steps\` is omitted from a manual command. Moving from the deployed
Docker setting to 2,000 steps would actually reduce training.

## Teacher data

The teacher model is intentionally not hard-coded or secretly called by this script.
Prepare a separate JSONL file using a teacher you are allowed to use, review every answer,
and keep the held-out prompts from \`data/fross_eval.jsonl\` out of it. Each line must be
one JSON object with non-empty \`user\` and \`assistant\` fields, optionally with \`history\`.
Use at least eight records; a few dozen or more diverse, high-quality examples are a better
starting point. Never include private conversations, passwords, API keys, or personal data.

Example format (not a claim that this example was generated by a teacher):

\`\`\`json
{"user":"Explain a Python list simply.","assistant":"A list stores items in order and can be changed after it is created. Example: fruits = [\"apple\", \"pear\"]."}
\`\`\`

This is teacher-answer supervised training (pseudo-labeling), not classic logit-level
distillation: the current FROSS implementation has no teacher-logit training path. The
teacher is not needed during inference; only the newly trained FROSS checkpoint is used.
The tokenizer and model weights are trained together from the combined text corpus.

## Run locally

Install the same PyTorch CPU dependency used by the service, then from the repository root:

\`\`\`bash
python experiments/compare_training.py
\`\`\`

That runs the two same-corpus variants. To include the teacher-augmented run:

\`\`\`bash
python experiments/compare_training.py --teacher-corpus data/fross_teacher_reviewed.jsonl
\`\`\`

The output folder \`experiments/results/\` contains each checkpoint, its generated answers,
and \`comparison.json\`. The generated checkpoints are experimental and are **not deployed
automatically**. Do not commit checkpoints or large generated files to Git.

You can reduce the steps for a quick smoke test:

\`\`\`bash
python experiments/compare_training.py --baseline-steps 12 --long-steps 20 --block-size 64 --merges 32 --output-dir /tmp/fross-comparison
\`\`\`

This short run tests the pipeline, not model quality.

## How to compare

Read the same prompts for every variant in \`data/fross_eval.jsonl\`. Review whether the answer
is relevant, factually correct, coherent, follows the requested format, and avoids repetition.
The \`criteria\` field is a rubric, not a gold answer. Score each criterion consistently (for
example 0 = fails, 1 = partial, 2 = meets it) and compare total scores. Validation loss from
different corpora is not directly comparable; a lower value alone does not guarantee better
responses. Keep the existing deployed model until a candidate has passed the tests and a
manual quality review.
